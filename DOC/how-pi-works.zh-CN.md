# Pi 的工作原理

> 本文译自 [how-pi-works.md](../packages/coding-agent/docs/how-pi-works.md)。

Pi 负责协调模型请求、工具执行、上下文组装和会话存储。会话（session）是 Pi 对一次对话的记录，内容包括消息、工具调用及其结果、模型切换、上下文压缩以及其他事件。

会话中的消息和事件构成一棵树。树中的每一条路径就是一个分支（branch）。以当前条目结尾的那个分支称为活动分支（active branch），下一次模型请求所用的历史记录就来自这条分支。

## Agent 循环

用户提交的消息会被添加到活动分支上。Pi 根据系统提示词、活动分支、可用工具和模型设置构建模型请求，然后通过所选的模型提供方（provider）发送出去。

提供方以流式方式返回助手回复，回复中可以包含文本和工具调用。Pi 记录这条回复，逐个执行其中的工具调用，并记录执行结果。至此完成一轮（turn）。如果工具结果或排队中的消息需要再次请求模型，Pi 就开始下一轮；否则，本次运行（run）结束。

引导消息（steering message）在当前这一轮助手回复结束后进入对话。后续消息（follow-up message）则要等 agent 完成所有待处理的工作后才进入。中止（abort）会停止当前运行，并把排队中的消息退回到编辑器中。

## 上下文

活动分支提供对话历史。Pi 会把其中的会话条目转换成模型能够接受的用户消息、助手消息和工具结果消息。

Pi 以自身的基础指令为底，再加上自动发现的上下文文件，构建出系统提示词。请求中还会附带工具定义和技能（skill）描述。

技能的完整指令只在需要时才加载。扩展可以追加指令，也可以改写上下文。

提示词模板会在编辑器中的输入变成用户消息之前将其展开。选中的文件、图片、粘贴的文本以及 shell 输出都可以成为消息内容。

## 会话

持久化的会话以 JSONL 文件保存。树中的每个条目都有一个 ID，并指向自己的父条目。当前条目决定了哪一条是活动分支。

如果从较早的某个条目继续对话，就会在同一个文件中产生另一个分支。分叉（fork）和克隆（clone）则会把选定的历史复制到一个新的会话文件中。

模型上下文由活动分支重建而来。压缩（compaction）会插入一个摘要条目，在后续的模型请求中用它代替更早的消息。原始条目仍然保留在会话树中。

## 使用接口

交互模式（interactive mode）在终端中渲染会话和 agent 事件。打印模式（print mode）执行一条提示词，然后输出最终回复。JSON 模式以 JSONL 格式输出 agent 事件。

RPC 模式从 stdin 接收 JSONL 格式的命令，并把响应和事件写到 stdout。TypeScript SDK 则在同一进程内创建和控制 agent 会话。

所有这些接口使用的都是同一套 agent 和会话机制。

## 扩展与资源

扩展（extension）是加载到 Pi 进程中的 TypeScript 模块。扩展的工厂函数可以注册工具、命令、快捷键、模型提供方、事件处理器、渲染器和终端 UI。

技能提供按需加载的指令及配套文件。提示词模板提供可复用的消息文本。主题提供终端配色。Pi 包（Pi package）则通过 npm 或 git 分发这些资源。

## 信任与权限

在加载项目设置和资源之前，Pi 会先判定是否信任该项目。做出信任决定并加载完项目资源之后，Pi 才加载上下文文件。已启用的工具以 Pi 进程的操作系统权限运行。扩展也在该进程内执行。
